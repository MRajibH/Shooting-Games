# RIFTLINE — an original, realistic browser multiplayer shooter

## Context

The reference (games.polinkhan.com/arena) is a three.js r128 third-person shooter: one weapon
(plasma blaster, 30 ammo), free-for-all kill count, WASD/sprint/jump, shoulder swap, auto-respawn,
plain script files, desktop-only controls. It is fun but shallow: no weapon variety, no pickups,
no modes, no bots (empty when nobody is online), no mobile play, and no server-side fairness.

Goal: an **original** game in the same genre (own name, theme, art, map, sounds — nothing copied)
that is deeper, fairer and as realistic as a browser allows. Decisions: same genre but deeper,
Rust authoritative server + Rust/WASM shared sim, Vite client, desktop + mobile touch,
"polished core" scope, realistic look and feel.

## Direction: realistic

The game aims to look and play as realistically as a browser allows. Arcade features from the
first draft (dash, double jump, jump pads, low-poly art) are dropped.

| Area | Reference | RIFTLINE |
|---|---|---|
| Movement | run, sprint, jump | Real human speeds (walk 3 m/s, sprint 6 m/s forward only, crouch 1.5 m/s), 9.81 m/s² gravity, ~0.45 m jump, acceleration and momentum, crouch, lean, vault low cover, stamina |
| Weapons | 1 sci-fi blaster | 4 realistic weapon classes: assault rifle, SMG, pump shotgun, bolt-action sniper. Magazines, tactical vs empty reloads, fire modes, recoil patterns, sway, ADS |
| Ballistics | instant | Projectile bullets with muzzle velocity, gravity drop, travel time, damage falloff, thin-material penetration |
| Damage | flat HP | Hitboxes per body part (head / torso / limbs), headshot multipliers, armour plates, bleed-free fast pacing |
| Map | flat arena | One realistic urban/industrial map: PBR materials, cover, interiors, sight lines, vertical play by stairs and ladders |
| Rendering | flat neon | PBR, physical sky + sun, filmic tone mapping, soft shadows, SSAO, bloom, motion blur option, decals, muzzle flash and smoke particles |
| Audio | basic | Positional audio, distance-delayed gunshots, reverb by environment, footsteps per surface |
| Modes | FFA kill count | Slap Arena (open-hand melee: knockback, stagger, knockouts), Team Deathmatch, Domination (capture points) |
| Empty servers | nobody to play | Server-side bots fill rooms, leave as humans join |
| Fairness | client-trusting | Rust authoritative server, same Rust sim compiled to WASM for prediction, lag-compensated hits |
| Platforms | desktop | Desktop + mobile touch (twin stick, aim assist) |
| Rooms | one global arena | Quick play + private room codes (max 10 players) |

Art: CC0 assets (e.g. Poly Haven textures/HDRIs, Quaternius / Mixamo-style rigged characters
where licences allow) plus own models. Nothing taken from the reference game.

## Architecture

Rust for everything that must be authoritative or shared; TypeScript only for rendering, input and UI.
Players need nothing but a browser.

```
Cargo.toml          # Rust workspace
crates/
  sim/              # shared: constants, protocol (serde), movement; native for the server,
                    #   WebAssembly (wasm-bindgen, --features wasm) for browser prediction.
                    #   Uses libm so native and WASM results are bit-identical.
  server/           # axum + tokio: WebSocket /ws, room registry, one task per room
                    #   (60 Hz tick, 30 Hz snapshots), serves client/dist
client/             # Vite + TypeScript + three.js
  src/wasm/         # generated by `npm run wasm` (gitignored)
  src/protocol.ts   # TS mirror of crates/sim/src/protocol.rs
  src/net.ts        # socket, WASM prediction, reconciliation, 100 ms interpolation
  src/input.ts      # keyboard + mouse (touch later), one InputFrame per tick
  src/main.ts       # renderer, camera, scene
```

Next.js is deliberately not used: it adds nothing to a canvas game and its usual hosting
cannot hold WebSocket rooms. A Next.js site (accounts, leaderboards) can sit beside the game later.

Key netcode rules:
- Client sends numbered input frames each tick; never positions.
- Server owns movement, health, ammo, hits, pickups and score.
- Client predicts its own player with the WASM build of the same Rust code and replays unacknowledged inputs on each snapshot.
- Remote players render ~100 ms in the past, interpolated between snapshots.
- Shots carry the client's render time; the server rewinds hitboxes (cap 250 ms) to validate.
- Server validates fire rate, ammo and input ranges; caps message size and frames per message; sanitises names.

## Build order (each milestone playable)

1. **Skeleton** (done) — Rust workspace, Vite client, WASM prediction, rooms, reconciliation and interpolation, realistic movement constants and lighting baseline.
2. **Movement + map + character + Slap mode** (done) — collision in Rust, the map with PBR materials, stairs, vaulting, lean, stamina, camera collision, rigged animated soldier with procedural layers, Slap Arena.
3. **Combat** (done) — four weapons, projectile ballistics with drag and drop, recoil/sway/ADS, hitboxes and headshots, lag compensation, death and respawn. Deferred: armour plates and penetration of thin materials (to milestone 7).
4. **Modes + rooms** — team deathmatch and domination, round flow, quick play and room codes, scoreboard and results.
5. **Bots** — waypoint graph, combat behaviour, three difficulties, auto-fill.
6. **Mobile** — touch sticks, aim assist, responsive HUD, quality scaling.
7. **Polish** — rigged characters with animation blending and IK, post-processing, decals, positional audio, kill feed, hit markers, settings, tuning.

## Verification

- `npm test` (cargo test): movement determinism, real-world speeds and jump height, protocol JSON shape; later ballistics, hitboxes, mode scoring, lag-compensation rewind.
- `npm run dev`: Rust server + Vite; open two tabs and confirm movement sync.
- Simulated bad network (server-side latency/loss flag) at 150 ms / 5 % loss: own movement smooth, others not rubber-banding.
- Bot soak test: 10 bots for a full match, tick time under budget.
- Mobile viewport emulation: touch controls, HUD layout, frame rate.
- `npm run build && npm start`: one Rust binary serves the built client and the WebSocket.
